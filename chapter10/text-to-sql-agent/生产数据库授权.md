# 数据库权限与生产接入

我在本项目中把“模型可生成 SQL”和“数据库允许执行什么”分开。JSQLParser 只提供 AST，不替业务判断权限；JDBC 的 `setReadOnly` 和 `executeQuery` 也不承担授权职责。

项目名称是 `text-to-sql-agent`，路径是 `java-ai-course-examples/chapter10/text-to-sql-agent`。当前可运行方言是 H2，业务 schema 固定为 PUBLIC。DeepSeek 默认配置、Ollama、ChatGPT 都只影响 SQL 生成，不改变数据库权限。

## 本地已经做到的权限隔离

`ReadOnlyDatabaseFactory.createDemo()` 用局部管理员连接执行 `schema.sql` 和 `data.sql`，生成随机 reader 密码，仅对五张业务表授予 SELECT。应用 Bean、命令行演示和测试拿到的都是 reader 数据源，管理员数据源不会暴露给执行器。

`BusinessTablePolicy` 是业务允许范围；`SchemaInspector` 再与元数据求交集。只新增数据库表不会自动扩大 Agent 权限。生产系统应把这份静态策略替换为服务端可信身份对应的视图/表授权，不能信任问题文本里自报的租户或角色。

本地测试用 reader 直接尝试 DELETE、UPDATE、INSERT、DROP、CREATE，不调用护栏，也不调用 setReadOnly。测试不只要求抛异常，还会重新读取客户数量和姓名，证明业务数据未变。

## production 配置入口

设置 `SPRING_PROFILES_ACTIVE=production` 后，`DatabaseConfiguration.productionDataSource` 从 `TEXT2SQL_DB_URL`、`TEXT2SQL_DB_USER`、`TEXT2SQL_DB_PASSWORD` 读取现有 H2 数据库连接。这个 profile 不建表、不灌种子数据，不允许 sa 用户，要求预先创建好 SELECT 账号。账号名称不是权限证明，下面的验收仍然必须执行。

数据库管理员用独立流程准备 schema 与迁移；运行账号不能拥有 schema，不能获得管理员角色、GRANT OPTION、业务写入、DDL、文件/网络函数或自定义副作用函数的权限。密码由部署平台注入，不能写进 application.yml 或下载包。文件型 H2 在适用部署方式下还可以采用只读文件访问，不能把此选项当作跨数据库的通用开关。

## 接 PostgreSQL / MySQL 前要补齐的工作

当前包没有宣称支持这两种生产数据库。迁移时需要同步替换 JDBC 驱动、连接配置、SchemaInspector 的 catalog/schema 规则、大小写归一化、允许函数集、SQL 方言和回归用例。只把 JDBC URL 改掉不能完成迁移。

数据库权限按最小范围逐项确认：

| 项目 | PostgreSQL | MySQL |
| --- | --- | --- |
| 运行身份 | 独立 LOGIN role；非 owner，非超级用户，无 BYPASSRLS | 独立 user；无管理员角色 |
| 可读对象 | 仅所需 schema 的 USAGE 与指定安全视图/表的 SELECT | 仅指定视图/表的 SELECT |
| 禁止扩大范围 | 不授予未来所有表默认读取，不加入写角色；核对 PUBLIC 继承权限 | 不授予全库权限、FILE、EXECUTE、CREATE、写入或 GRANT OPTION |
| 副作用 | 核对可执行函数及 SECURITY DEFINER 函数的实际权限 | 核对存储函数、UDF 与文件权限 |
| 多租户 | 服务端身份到 RLS/安全视图，测试 owner/BYPASSRLS 绕过风险 | 服务端身份到授权视图/租户条件，执行跨租户拒绝测试 |
| 资源控制 | 服务端 statement_timeout、连接池、并发与资源隔离 | 对应版本的服务端查询时间限制、连接池、并发与资源隔离 |

## 上线验收

在隔离验收库里，以真实部署的运行账号完成：正常 SELECT 成功；业务 INSERT/UPDATE/DELETE 和 DDL 失败且数据未变；未授权表、其他 schema 的同名表、跨租户数据不可读；文件/网络/有副作用函数不可调用；长查询能被数据库端超时控制；完整应用链路对越权 SQL 返回 BLOCKED_BY_GUARD。

JDBC 的最大行数只限制返回结果，不限制数据库扫描或排序工作量。SQL 护栏和数据库授权都通过后，还要检查真实模型的业务口径、执行计划和延迟。

参考：[H2 授权命令](https://h2database.github.io/html/commands.html)、[PostgreSQL GRANT](https://www.postgresql.org/docs/current/sql-grant.html)、[JSQLParser 用法](https://jsqlparser.github.io/JSqlParser/usage.html)。解析器升级时重跑本项目全部安全反例，不直接照抄新版本 Visitor API。
